## This repo
- SHOWHAUS Studio (exterior 3D massing model for agencies; never call it a walkthrough — that word is for interiors you walk, `walk/`): page `dist/showhaus/studio/` (showhaus.app/studio/?p=<slug>), embed `studio/embed.js`, pilot `studio/pilot.html`, Worker routes `src/studio.js` (`/pay/studio-pilot`, `/api/studio-config`).
- Studio data: `python3 scripts/showhaus_studio_build.py <slug>` reads `showhaus/studio/<slug>.source.json` (figures + URLs from the planning documents) → `dist/showhaus/studio/data/<slug>.json`. Email kit: `node scripts/showhaus-studio-kit.mjs <slug>` (Playwright + ffmpeg). Judge: `node scripts/showhaus-studio-judge.mjs`; unit tests: `node --test scripts/showhaus-studio.test.mjs`.
- SHOWHAUS listing kits: `node scripts/showhaus-listing-kit.mjs "<address>" --slug <slug>` → `dist/showhaus/p/<slug>.json` + media; judge `node scripts/showhaus-kit-judge.mjs`. See `docs/showhaus-listing-kit.md`.
- SHOWHAUS claim flow: page `dist/showhaus/claim/` (showhaus.app/claim/?p=<slug>), Worker `src/claim.js` (`/api/claim/*`, share links `/s/<slug>/<code>`; D1 tables `sh_claims`, `sh_claim_files`, `sh_claim_rate` in OPS_DB). Verified = emailed 6-digit code confirmed for that work address AND its domain matches the company website (domain match alone stays pending); pending claims + evidence files are on the CVF OIDC side (`/api/ops/summary` → `claims`, `/api/ops/claim-file?id=`). Tests: `node --test scripts/showhaus-claim.test.mjs`; click-through `node scripts/showhaus-claim-judge.mjs --base <url>` (`--explainer` re-records the 10 s video, `--email` re-renders the draft email previews in `showhaus/outreach/claim-arncliffe-central/`).
- SHOWHAUS walk (interior walkthroughs, base tier → photoreal tier): gallery `dist/showhaus/walk/` (showhaus.app/walk/), one home `showhaus.app/walk/?p=<slug>`. A listing is `walk/data/<slug>.json` (`project` for the claim flow, `listing.source` = `plan` | `estimate` picks the basis line) + `walk/data/<slug>/` (`room.js` baked mesh, `atlas_*.jpg`, photoreal `photo*.jpg` / clips named in `room.js` views, `poster.jpg`) + one row in `walk/data/index.json` (`lngLat` = map pin, `null` = gallery only). Scene files come from the plan-to-walkthrough pipeline (Blender bake, outside this repo). Claim reuses `src/claim.js` (a slug is a Studio project or a walk listing; `/api/claim/public?p=` drives the Owner-claimed badge). `upgrade_interest` events are the demand count for the photoreal tier (net of `upgrade_interest_cancel`), and the card promises visitors that homes with the most votes are made photoreal first — the render queue must follow that order; no price is shown until GPU cost per home is set. Tests: `node --test scripts/showhaus-walk.test.mjs`; click-through, desktop + phone: `node scripts/showhaus-walk-judge.mjs` (starts `scripts/showhaus-local-worker.mjs`, the real Worker on localhost; `--poster` re-renders the poster).
- SHOWHAUS owner controls on a walk listing (in `src/claim.js`, shown on the claim page's last step): **private** — only a verified claimant can turn it on (`/api/claim/private`, or `intent=private` on submit, applied when the claim verifies); a private listing returns 410 for `walk/data/<slug>.json` and `walk/data/<slug>/*` (`src/worker.js`), and the viewer, gallery and map show "This home has been made private at the builder's request." **Real finishes** — paid by the claimant (storage + AI render): `/api/claim/finishes` records the request; a price exists only when `FINISHES_PRICE_LABEL` and `FINISHES_PAYMENT_LINK` (Stripe) are both set; `/pay/finishes` tags the checkout `fin_<claim id>`, the Stripe webhook marks it paid, and only then `/api/claim/finishes-file` accepts files (D1 `sh_finish_files`; read via `/api/ops/claim-file?id=&f=`). The re-render itself is the plan-to-walkthrough pipeline, outside this repo. `/api/ops/summary` → `claims.private`, `claims.private_pending`, `claims.finishes`. Click-through: `node scripts/showhaus-private-judge.mjs`.
- SHOWHAUS no-login input (`src/suggest.js`): gallery "suggest a home" takes a NSW street address (autocomplete `GET /api/suggest/address?q=` proxies the NSW address register GURAS once the text starts with a house number (Sydney-closest first), and Photon (OSM) street names before that (`kind: street`; picking one puts the cursor in front for the number); the box is wired before the gallery loads; the map search links a typed street address to `/walk/?a=`; on submit the address is checked there for a map point, unknown new lots are kept `verified:false`; key `addr:<REGISTER FORM>`, point in D1 `sh_suggest_geo`) or a link to an already-published plan (`/api/suggest/home`; no files; the same link adds up as votes; submitted links are never shown to visitors) and the viewer takes a one-line mistake report (`/api/suggest/fix`). Both are rate-limited per connection; an optional email on a suggestion is kept only until `POST /api/ops/suggest-built {url, slug}` (OIDC) sends the one "ready to walk" email, then deleted. Read side `/api/ops/summary` → `suggestions` (`homes`, `fixes`) and `queue` = the build order the pages promise (`base`: asked-for homes by votes, rows `kind: link | address` with `key` — an address has no plan, so its base walk is the satellite estimate, `listing.source = estimate`; report it built with `url = key`; `photoreal`: live walks by net votes; `finishes`: paid, oldest first). Address-only homes: `python3 showhaus/walk-pipeline/estimate.py "addr:<KEY>" --slug <slug> --out <dir>` → an estimate plan JSON from the NSW lot, road and aerial imagery + `aerial.jpg` to check (README there). Base-walk builder: `showhaus/walk-pipeline/walkgen.py <plan.json> check | preview | bake | pack` (any rectilinear one-space plan JSON → scene files; schema and limits in the README there; `pip install bpy`). Tests: `node --test scripts/showhaus-walkgen.test.mjs`. Taking the next home from `queue.base`: the nightly scheduled task "SHOWHAUS 야간 워크 굽기" (00:41 Sydney) reads the queue through CVF `showhaus-walk-queue.yml` (OIDC; suggested links stay in CVF farm-state, never in this public repo), reads the plan into JSON, bakes, PRs, merges and then dispatches `built` → `/api/ops/suggest-built`. Photoreal lane: `node scripts/showhaus-photoreal-queue.mjs plan|job <walk-queue.json>` turns `queue.photoreal` into the next render job (votes order, skips done/private/non-gallery homes, no votes → no job); the GPU step itself is plan-to-walkthrough §4. Tests: `node --test scripts/showhaus-photoreal-queue.test.mjs`. Click-through: `node scripts/showhaus-suggest-judge.mjs`.
- SHOWHAUS Hunt board (the "hunting" stage of the lifecycle: homes someone is looking at, from any site): page `dist/showhaus/hunt/` (showhaus.app/hunt/, `?q=` pre-fills, `?b=<id>` = a shared board), Worker `src/hunt.js`: `GET /api/hunt/check?q=` (a Domain link is read for its address from the URL slug, a realestate.com.au link only gives the suburb so the page asks for the street; the listing site is never fetched; GURAS → point → NSW Planning Portal zoning / bush fire / flood, Western Sydney ANEC, canopy; unknown stays unknown), `POST /api/hunt/board` (share → `{id, edit}`; re-post with both to update; D1 `sh_hunt`), `GET /api/hunt/board?id=`, `POST /api/hunt/comment` (`sh_hunt_comments`). Own boards live in the browser (`localStorage sh_hunt`); rent on each card is computed in the page from `data/rents.json` by postcode and bedrooms. The homepage start screen's paste box submits to `/hunt/?q=`. Tests: `node --test scripts/showhaus-hunt.test.mjs`. Events: `hunt_view`, `hunt_add`, `hunt_remove` (client), `hunt_check`, `hunt_share`, `hunt_comment` (server).
- SHOWHAUS arrange (furniture layout, no bake; the "moving in" stage): page `dist/showhaus/arrange/` (showhaus.app/arrange/ for movers — tape-measure room `?room=WxD`, sample plans, send a plan link; `?for=listing` for vendors, landlords and agents; `?p=<slug>` a plan, `&view=listing` the buyer-view banner; `?b=<id>#e=<edit>` a shared layout, edit token also in localStorage `sh_arr_edit:<id>`). Geometry shared by page and Worker: `dist/showhaus/walk/plan-core.js` (catalogue mirrors walkgen ITEMS, wall collision, snap, clearances, `cleanLayout`); three.js room built in the browser from plan JSON: `dist/showhaus/walk/plan-room.js` (hemisphere + sun, contact-shadow AO). Plans: `node scripts/showhaus-arrange-plans.mjs` copies `PUBLISH` from `showhaus/walk-pipeline/plans/` to `dist/showhaus/arrange/plans/` (a plan is arrangeable as soon as it passes `walkgen.py check`; the walk viewer links "Arrange your own furniture" for those). Worker `src/arrange.js`: `POST/GET /api/arrange/board` (D1 `sh_arrange`). Plan schema has internal walls and room labels (`walls`, `spaces`; README there). Events: `arrange_view`, `arrange_start`, `arrange_add`, `arrange_3d`, `arrange_copy` (client), `arrange_share` (server). Tests: `node --test scripts/showhaus-arrange.test.mjs`.
- SHOWHAUS address pages (`src/place.js`): `showhaus.app/p/<slug>` for every NSW register address (slug = GURAS address, lower case, dashes; `4/17 FLOOD STREET CLOVELLY` → `4-17-flood-street-clovelly`), rendered by the Worker on request (edge-cached a day) with the hunt checks (`src/hunt.js` `checkPoint`/`summarise`, incl. Sydney Airport ANEF 2039 from Randwick Council's GIS and `/api/hunt/noise?ll=`) and postcode rents from `dist/showhaus/data/place-lookup.json` (rebuild with `python3 scripts/showhaus_place_data.py` after the rent data changes). The register is read through SIX Maps `public/NSW_Query/MapServer/0` first (answers from anywhere; no geometry, so points come from `returnExtentOnly`; boxes by `returnIdsOnly` then ids in 1000s) and the GURAS FeatureServer second (it times out outside Australia). A slug that is a listing kit redirects to `/p/?a=`; not in the register → 404 with real neighbours, never a guessed page. `/p/go?q=` = paste box target (address or listing link → page). `/sitemap.xml` → 0.01° tiles over Greater Sydney (`/sitemaps/<x>_<y>.xml`, GURAS envelope query, cached a week); `/robots.txt`. Tests: `node --test scripts/showhaus-place.test.mjs`.
- SHOWHAUS room (scan your own things, place them; no server, no model API): page `dist/showhaus/room/` (showhaus.app/room/). ① scan: open-weight models run in the visitor's browser through transformers.js from jsDelivr (`room/vision.js`: DETR boxes, SlimSAM cut-out — this export takes points only, so a box becomes depth-chosen positive points + outside negatives — Depth Anything v2 relative depth); `room/mesh.js` turns mask + depth into a 2.5D relief (front from the photo, back mirrored; never call it a full 3D scan) and estimates size from typical sizes per detector label (`PRIORS`), photo angle aware; kept objects live in the browser's IndexedDB `sh_room`. ② place: a room photo (shadow catcher + SAM wall repaint), an arrange plan or a tape room (`walk/plan-room.js`), one object at a time; sentences (Korean/English) go through `room/intent.js` `parse` → ops → pure `apply`, the renderer is fixed; every op is a timeline step (localStorage `sh_room_steps`), tapping a step reopens it, a new change branches. Events: `room_view`, `room_scan`, `room_detect`, `room_segment`, `room_keep`, `room_space`, `room_place`, `room_say`, `room_rewind`. Tests: `node --test scripts/showhaus-room.test.mjs`; click-through with the real models (5–10 min on CPU): `node scripts/showhaus-room-judge.mjs --base <url> [--phone]`. Probe any photo (taps the middle of every detected thing, prints name/size/hint per tap): `node scripts/showhaus-room-probe.mjs --photo <jpg> [--photo …] [--phone]`; COCO val2017 photos (images.cocodataset.org) make good probes. Model host down: `node scripts/showhaus-room-fault.mjs` (answers the hub with 429: a blip must recover by itself, a long outage must blame the host and offer Try again). A thing with no typical size and no name shows one-tap rough heights (`ROUGH`) and cannot be kept until one is picked or a size typed.
- SHOWHAUS Room for Android: install page `dist/showhaus/app/` (showhaus.app/app/) serves `showhaus-room.apk`, built in in-c0/spatial-world-engine `apps/showhaus-android` (`./gradlew :app:assembleRelease`); copy the new APK over it and bump the version line on the page. Events `app_view`, `app_download`.
- SHOWHAUS Pro (monthly plans for agencies and builders): page `dist/showhaus/pro/` (showhaus.app/pro/, `?plan=`, `?welcome=<plan>` after Stripe), Worker `src/subscribe.js`: `PLANS` (agent 149, agency 500, builder 500 AUD/month) is the one source of truth for page, Worker and Stripe; `/pay/pro?plan=&src=` → Payment Link from var `PRO_LINK_<PLAN>` (none set → back to the free-listing form), `/api/pro-config`, `POST /api/pro/start` (free first listing; D1 `sh_pro_requests`, event `pro_start`). Stripe: `scripts/showhaus-stripe-setup.mjs [--apply --put-secret]` where `STRIPE_SECRET_KEY` exists (product, prices `showhaus_pro_<plan>`, links, webhook, vars); webhook adds `subscription_started|renewed|cancelled`. Read side without OIDC: `src/entry.js` (wrangler `main`) exports `OpsFeed.summary()` for CVF ji-line's service binding `SHOWHAUS_OPS`; `/api/ops/summary` → `pro`. Tests: `node --test scripts/showhaus-pro.test.mjs`.
